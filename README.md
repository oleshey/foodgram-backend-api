# 🍽️ Foodgram

**Foodgram** — это веб-приложение для публикации рецептов, позволяющее пользователям делиться кулинарными идеями, подписываться на других авторов, добавлять рецепты в избранное и формировать список покупок из ингредиентов.

## 📋 Возможности

- **Регистрация и авторизация** — создание аккаунта и вход через токен-аутентификацию (Djoser)
- **Управление рецептами** — создание, редактирование и удаление рецептов с фотографиями, описанием, временем приготовления, тегами и ингредиентами
- **Загрузка изображений** — поддержка загрузки фото рецептов в формате Base64 (data URI)
- **Теги и ингредиенты** — гибкая система тегов для категоризации рецептов и ингредиентов с единицами измерения
- **Подписки** — возможность подписываться на других пользователей и просматривать их рецепты в ленте
- **Избранное** — сохранение понравившихся рецептов в отдельный список
- **Список покупок** — добавление рецептов в корзину и скачивание сводного списка ингредиентов в формате TXT
- **Короткие ссылки** — автоматическая генерация коротких ссылок на каждый рецепт
- **Пагинация и фильтрация** — удобная навигация по рецептам с фильтрацией по автору, тегам, избранному и корзине
- **Админ-панель** — встроенная Django Admin для управления всеми сущностями

## 🛠 Стек технологий

### Backend
- **Python 3.12** — язык программирования
- **Django 5.1** — веб-фреймворк
- **Django REST Framework 3.15** — создание REST API
- **Djoser 2.3** — аутентификация и управление пользователями (токены)
- **PostgreSQL 13** — реляционная база данных
- **Gunicorn 25** — WSGI-сервер для продакшена

### Frontend
- **React 17** — UI-библиотека
- **React Router 5** — маршрутизация
- **Create React App 5** — сборка фронтенда

### Инфраструктура
- **Docker & Docker Compose** — контейнеризация и оркестрация
- **Nginx** — reverse proxy и раздача статики
- **GitHub Actions** — CI/CD: тестирование, сборка образов, деплой на сервер
- **Telegram** — уведомления о статусе деплоя (опционально)

## 🚀 Развертывание проекта

### Требования

- [Git](https://git-scm.com/)
- [Docker](https://www.docker.com/) и [Docker Compose](https://docs.docker.com/compose/) (v2+)

### Локальный запуск

1. **Клонируйте репозиторий:**
   ```bash
   git clone <repo_url>
   cd foodgram
   ```

2. **Настройте переменные окружения** (см. раздел ниже):
	```bash
	cp .env.example .env
	# Отредактируйте .env
   ```
3. **Запустите проект через Docker Compose:**
	```bash
	docker compose up --build
   ```
	Приложение будет доступно по адресу: **[http://localhost:8000](http://localhost:8000)** (порт может отличаться в зависимости от конфигурации).

### Запуск в продакшене

1. Настройте сервер (VPS) с установленными Docker и Docker Compose.
2. Настройте SSH-доступ для CI/CD (если используете автоматический деплой).
3. Скопируйте `docker-compose.production.yml` на сервер и выполните:
	```bash
	sudo docker compose -f docker-compose.production.yml pull
	sudo docker compose -f docker-compose.production.yml up -d
   ```

### Альтернативный запуск (без Docker)

Для разработки можно запустить проект локально без Docker:

```bash
cd backend
python -m venv venv
source venv/bin/activate  # или venv\\Scripts\\activate на Windows
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Однако для полноценной работы с медиа-файлами и статикой рекомендуется использовать Docker-сборку.

## ⚙️ Настройка `.env`

Скопируйте шаблон и настройте переменные:

```bash
cp .env.example .env
```

### Переменные окружения

| Переменная | Описание | Пример |
| --- | --- | --- |
| `POSTGRES_DB` | Имя базы данных PostgreSQL | `foodgram` |
| `POSTGRES_USER` | Пользователь PostgreSQL | `foodgram_user` |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL | `strong_password_here` |
| `SECRET_KEY` | Секретный ключ Django (**обязательно задайте свой!**) | `django-insecure-...` |
| `DEBUG` | Режим отладки (`True`/`False`) | `False` |
| `ALLOWED_HOSTS` | Разрешённые хосты (через запятую) | `127.0.0.1,localhost,foodgram.example.com,backend` |
| `CSRF_TRUSTED_ORIGINS` | список Origins для проверки CSRF | `https://foodgram.example.com` |
| `DB_HOST` | Хост базы данных (в Docker — `db`) | `db` |
| `DB_PORT` | Порт базы данных | `5432` |

> ⚠️ **Важно:** Переменная `SECRET_KEY` обязательна и должна быть уникальной. Для продакшена всегда устанавливайте `DEBUG=False` и указывайте реальные хосты в `ALLOWED_HOSTS`.

## 📚 Документация API

Основные эндпоинты:

- **`/api/users/`** — регистрация, список пользователей, профиль
- **`/api/auth/token/login/`** — получение токена авторизации
- **`/api/tags/`** — список тегов
- **`/api/ingredients/`** — список ингредиентов (с фильтром по названию)
- **`/api/recipes/`** — создание, список, детали, обновление и удаление рецептов
- **`/api/recipes/{id}/favorite/`** — добавление/удаление из избранного
- **`/api/recipes/{id}/shopping_cart/`** — добавление/удаление из корзины покупок
- **`/api/recipes/{id}/get-link/`** — получение короткой ссылки на рецепт
- **`/api/users/{id}/subscribe/`** — подписка/отписка на пользователя
- **`/api/users/subscriptions/`** — список подписок текущего пользователя
- **`/api/recipes/download_shopping_cart/`** — скачивание списка покупок в TXT
